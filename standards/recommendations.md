# Proposals and unresolved source examples

Maintainer: AVI repository maintainers. Extracted 2026-10-12.
Status is recorded per rule; adopted means carried forward from the source standards, not a new team approval.

## AVI-REC-001

Status: **recommendation**. Applicability: When explicitly evaluating operational conventions.

Structured error/logging conventions, translation strategy, environment conventions and performance monitoring remain team-review proposals. Discover existing implementations and declared packages before proposing adoption; do not install or mandate them as adopted standards.

## AVI-REC-002

Status: **recommendation**. Applicability: When explicitly evaluating hooks or bundle analysis.

Husky/lint-staged/Commitlint and bundle-analysis examples are proposals. Confirm dependencies, builder output, supported task flags and team choices before implementation. Proposed thresholds are not universal budgets.

## AVI-UNVERIFIED-001

Status: **unverified**. Applicability: Interpreting legacy examples.

Source examples contain old *ngFor alongside modern control-flow prose, constructor-effect rules alongside lifecycle/input mocks, and Signal Store entity-map assumptions that require installed API verification. These examples are illustrative, not normative implementation templates. Cite an unresolved contradiction instead of promoting it to a new requirement.
